# מערכת ניהול סקרים — בוט Telegram + ממשק ניהול ב-Java Swing

מערכת המנהלת קהילה גלובלית של משתמשים הרשומים לבוט Telegram, מאפשרת ליצור סקרים
(ידנית או באמצעות ChatGPT API), לשלוח אותם לחברי הקהילה, לעקוב אחר ההשתתפות בזמן אמת
ולהציג את התוצאות.

---

## הפעלה

### 1. יצירת בוט ב-Telegram

1. פתחו שיחה עם **@BotFather** בטלגרם.
2. שלחו `/newbot` ובחרו שם ושם משתמש (חייב להסתיים ב-`bot`).
3. שמרו את ה-**Token** שקיבלתם ואת שם המשתמש.

### 2. הרצה

```bash
mvn clean package
java -jar target/telegram-poll-system.jar
```

או ישירות:

```bash
mvn exec:java
```

בהפעלה הראשונה ייפתח **חלון הגדרות** שבו מזינים את שם המשתמש של הבוט, את הטוקן,
ואופציונלית מפתח OpenAI API. הנתונים נשמרים בקובץ `config.properties` לצד התוכנית,
וניתן לשנותם בכל רגע דרך כפתור **הגדרות** בראש החלון.

לחלופין ניתן להגדיר משתני סביבה:
`TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_BASE_URL`.

#### ספק ה-AI

`ChatGptService` מממש את פרוטוקול **OpenAI Chat Completions**. ברירת המחדל היא ה-API הרשמי
של ChatGPT, אך מכיוון שכתובת השרת נקראת מההגדרות ולא מקודדת בקוד, אפשר לבחור בחלון ההגדרות
כל שירות תואם — בלי לשנות שורת קוד:

| ספק | כתובת | מודל לדוגמה |
|---|---|---|
| ChatGPT (OpenAI) | `https://api.openai.com/v1/chat/completions` | `gpt-4o-mini` |
| Google Gemini | `https://generativelanguage.googleapis.com/v1beta/openai/chat/completions` | `gemini-2.0-flash` |
| Groq | `https://api.groq.com/openai/v1/chat/completions` | `llama-3.3-70b-versatile` |

השירות שולח תחילה בקשה עם `response_format: json_object`, ואם הספק אינו תומך בכך (מחזיר 400)
הוא חוזר על הבקשה בלעדיו ומנקה סימוני קוד מהתשובה — כך אותו קוד עובד מול כל הספקים.

### 3. הגשה בקובץ יחיד

הקובץ `submission/Main.java` הוא איחוד אוטומטי של כל המחלקות לקובץ אחד
(נוצר על ידי `python3 tools/merge_single_file.py`) — מיועד להדבקה בתיבת ההגשה.
הוא זהה בפונקציונליות לפרויקט המלא ודורש את אותן שתי הספריות.

## מימוש דרישות המטלה

| הדרישה | היכן ממומש |
|---|---|
| הצטרפות ב-`/start` / `היי` / `Hi` בלבד | `SurveyBot.handleTextMessage` |
| אין הצטרפות כפולה | `CommunityService.join` מחזיר `null` לחבר קיים |
| שידור לכל שאר החברים עם שם וגודל קהילה | `SurveyBot.handleTextMessage` + `getMembersExcept` |
| הצגת הקהילה בזמן אמת (שם, username, שעת הצטרפות, סה"כ) | `CommunityPanel` + `CommunityListener` |
| 1-3 שאלות, 2-4 אפשרויות | `Poll.MIN/MAX_QUESTIONS`, `Question.MIN/MAX_OPTIONS`, ולידציה חיה ב-UI |
| יצירה ידנית / באמצעות ChatGPT | `CreatePollPanel` + `ChatGptService` |
| הצגת שאלות ה-ChatGPT לעריכה לפני שליחה | `CreatePollPanel.loadQuestions` |
| שליחה מיידית / מושהית + Countdown חי | `PollService.schedulePoll`, `LivePollPanel` (מסך ספירה + מד התקדמות) |
| הודעה ברורה כשהסקר נשלח בפועל | `MainWindow.onPollStarted` — באנר ירוק + שינוי מסך |
| מינימום 3 חברים | `PollService.schedulePoll` + הודעה בפאנל הקהילה |
| משתתפי הסקר = צילום מצב של הקהילה בתחילתו | `Poll.startWithParticipants` |
| מצטרף באמצע לא נכנס לסקר הפעיל | `Poll.isParticipant` → `NOT_PARTICIPANT` |
| תשובה אחת לכל שאלה, ללא שינוי | `ParticipantProgress.recordAnswer` |
| מעקב `x/n` + מצב לכל משתתף בזמן אמת | `LivePollPanel` + `PollListener.onAnswerReceived` |
| 5 דקות מקסימום / סגירה מוקדמת כשכולם השלימו | `PollService.closePoll`, `Poll.allParticipantsCompleted` |
| אין קבלת תשובות לאחר סגירה | `Poll.registerAnswer` בודק `status == ACTIVE` |
| תזכורת אחת אחרי 3 דקות, רק למי שלא סיים | `PollService.sendReminders` + `markReminderSent` |
| אין תזכורות אם הסקר נסגר קודם | `sendReminders` יוצא כשהסטטוס אינו `ACTIVE` |
| תוצאות ממוינות לפי שכיחות + אחוזים | `Question.getSortedResults`, `ResultsPanel` |
| סקר פעיל אחד בלבד | `PollService.hasLivePoll` |
| הקהילה נשמרת אחרי סיום סקר | `CommunityService` נפרד לחלוטין מ-`Poll` |

### הפרדת נתונים גלובליים מנתוני סקר

`Member` (קהילה) **אינו מכיל** שדה "ענה / לא ענה". מצב המענה נשמר ב-`ParticipantProgress`
השייך לסקר מסוים, ולכן אותו משתמש יכול להשלים סקר אחד, לדלג על השני ולענות חלקית בשלישי —
בלי שהמידע הגלובלי עליו ישתנה.

## דגשי UX/UI

- **חיווי מצב קבוע בראש החלון**: שבב שמעודכן כל שנייה ואומר תמיד מה מצב המערכת —
  "אין סקר פעיל" / "⏳ ממתין לשליחה · 02:31" / "● סקר פעיל · נותרו 04:12" /
  "■ הסקר נסגר · התוצאות מוכנות". המפעיל אף פעם לא נשאר בחוסר ודאות, בכל לשונית שהוא נמצא.
- **RTL מלא** בכל הממשק, כולל טבלאות, מדי התקדמות וגרפי תוצאות. הכיווניות מוחלת על
  העץ רק לאחר שהוא נבנה במלואו, וכן על כל רכיב שנוצר בזמן ריצה (שאלה שנוספה, שאלות
  שהתקבלו מ-ChatGPT, כרטיסי התוצאות) — אחרת אותם רכיבים היו מוצגים הפוך.
- **החלון נפתח ממוקסם** לגודל המסך בפועל, כדי שטבלת המעקב וגרפי התוצאות יקבלו מקום.
- **פאנל קהילה קבוע** בצד המסך — נראה תמיד, בכל לשונית.
- **ולידציה חיה**: כפתור "התחל סקר" מושבת, ולצידו משפט אחד שמסביר *בדיוק* מה חסר.
- **באנר התראה** בראש החלון לכל אירוע משמעותי (סקר נשלח / תזכורות נשלחו / הסקר נסגר).
- **מצבי ריק** מנוסחים ומסבירים מה לעשות הלאה, במקום מסך לבן.
- **מעברי לשוניות אוטומטיים**: יצירה → סקר פעיל → תוצאות, לפי מצב המערכת.
- **שורת סטטוס** קבועה עם הפעולה האחרונה ושעון.
- **משוב מלא בבוט**: אישור לכל תשובה, התקדמות `x/n`, חסימה מנומקת של תשובה חוזרת,
  והודעת סיום אישית.

## בדיקות

`verify/LogicTest.java` מריץ 63 בדיקות על כל כללי המערכת (הצטרפות, הקפאת משתתפים,
תשובה כפולה, סגירה מוקדמת, תזכורות, מיון תוצאות, דחיית קריאות חוזרות פגומות,
ואי-אפשרות הצטרפות כפולה) — כולן עוברות.

### הערות מימוש שנובעות מהבדיקות

- **אף קריאת רשת אינה מתבצעת על ה-Event Dispatch Thread.** שליחת סקר ל-N חברים היא
  N בקשות HTTPS; `PollService` משנה את המצב באופן סינכרוני (כדי שצילום המשתתפים יילקח
  בדיוק ברגע הלחיצה) ומעביר את השליחה עצמה ל-thread רקע. הממשק לא נתקע גם בקהילה גדולה.
- **מצב מול רשת מופרדים בנעילה אחת.** כל שינוי מצב מתבצע תחת `lock` יחיד, אך אף בקשת
  Telegram אינה נשלחת בתוך הנעילה — כך תשובה שמגיעה בדיוק ברגע הסגירה מדווחת כ"הסקר נסגר"
  ולא כ"כבר ענית".
- **הסגירה עצמה מיידית**, כפי שהכללים מחייבים: ברגע שכל המשתתפים השלימו, הסטטוס עובר
  ל-CLOSED ותשובות נוספות נדחות. רק *הודעות* הסגירה בטלגרם נדחות ב-400ms, כדי שהמצביע
  האחרון יקרא קודם "סיימתם את הסקר" ורק אחר כך "הסקר נסגר".
